# Пробую

«Пробую» — веб-приложение с AI-наставником для детей 8–14 лет и их родителей. Оно помогает превратить детский вопрос в понятное объяснение, небольшую безопасную пробу, действие и осмысление результата.

`вопрос → объяснение → безопасная проба → действие → результат → рефлексия → следующий шаг`

Продукт поддерживает любопытство и самостоятельность. Он не ставит диагнозы, не оценивает способности и не определяет профессию ребёнка.

## Что можно посмотреть сейчас

В репозитории опубликованы фиксированная демонстрация исследовательского сценария и локальный учебный сценарий управления семьёй и доступом. В демонстрации посетитель проходит заранее подготовленный пример: вопрос, объяснение, пробу, выбор результата, добровольную рефлексию и нейтральное наблюдение по одному эпизоду.

Демонстрация использует только синтетический контент. Она не принимает свободный ввод, не создаёт детский профиль, не вызывает внешнюю AI-модель, не подключает аналитику и не сохраняет данные в браузерных хранилищах.

Сейчас реализованы:

- React-интерфейс на TypeScript и Vite;
- компоненты shadcn/ui на Radix Primitives и собственные дизайн-токены;
- Fastify API и worker в одном модульном backend;
- OpenAPI-контракт и сгенерированный клиент;
- PostgreSQL и проверяемые Drizzle-миграции;
- синтетический seed демонстрационного сценария;
- семейный интерфейс с родительским и детским режимами общего браузера;
- серверные сессии, согласия, пауза и отзыв доступа браузера;
- изоляция семей в PostgreSQL и повторное подтверждение чувствительных действий;
- unit-, API-, DB integration- и browser E2E-проверки.

Семейный сценарий доступен только локально с вымышленными семьями и учебными кодами. Он позволяет проверить интерфейс и серверные ограничения, но не подтверждает возраст или полномочия взрослого. Настоящий вход, реальные детские данные и внешний AI пока не включены. Это техническая демонстрация, а не готовый сервис для семей.

## Структура

```text
apps/web/             React-приложение
services/backend/     API и worker
packages/ui/          UI-компоненты и дизайн-токены
contracts/openapi/    Сетевой контракт и сгенерированный клиент
contracts/events/     Схемы продуктовых событий
infra/                Локальная инфраструктура
```

## Локальный запуск

Нужны Node.js 24.19.0 LTS, Corepack/pnpm 11.19.0 и Docker с Compose.

```bash
nvm use
corepack enable
pnpm install --frozen-lockfile
pnpm contract:generate
pnpm db:up
pnpm db:migrate
pnpm db:seed
pnpm dev
```

После запуска:

- web: `http://127.0.0.1:5173`;
- API health: `http://127.0.0.1:3100/v1/health`;
- демонстрационный сценарий: `http://127.0.0.1:3100/v1/demo/scenarios/paper-fall`.

Остановка PostgreSQL без удаления локального Docker volume:

```bash
pnpm db:down
```

## Локальный семейный сценарий

После установки зависимостей и запуска PostgreSQL выполните:

```bash
pnpm dev:m2
```

Откройте `http://127.0.0.1:5174/family`. Команда применяет миграции к отдельной локальной базе `probyu_m2_dev`, запускает API на порту 3102 и web на 5174. База демонстрации `probyu` остаётся отдельной.

1. Выберите вымышленную семью Аврора или Комета и войдите с показанным учебным кодом.
2. Ознакомьтесь с согласиями: разрешение истории необязательно. Создайте профиль с фиксированным псевдонимом и возрастной группой.
3. Передайте браузер ребёнку, затем проверьте возврат в родительский режим, изменение согласий, паузу и отзыв доступа. Чувствительные действия требуют отдельного учебного кода.

Учебные коды намеренно видны для ручной проверки и не являются настоящей авторизацией взрослого. Свободного ввода вопросов и вызовов AI здесь нет. Семейные ответы не кешируются; credentials и детский контент не записываются в browser storage. Сессия использует HttpOnly cookie.

Ключи сессий и локального proxy создаются при запуске и остаются в серверных процессах. После перезапуска старый вход перестаёт работать — выберите «Начать новый вход». Семейный сценарий открывайте через web-порт: прямые семейные запросы к API в этом режиме отклоняются. Обычный `pnpm dev` не включает семейную авторизацию; учебный adapter запрещён в production.

## Проверка

Полная проверка кода, контрактов, типов, тестов и production-сборки:

```bash
pnpm verify
```

Отдельные интеграционные и браузерные сценарии:

```bash
pnpm test:integration
pnpm test:e2e
```

Browser E2E проверяет desktop и mobile Chromium, клавиатурный и touch-сценарии, сетевые ошибки, повтор, reflow, reduced motion, WCAG 2.2 AA и отсутствие browser persistence.

Семейные проверки запускаются последовательно:

```bash
pnpm db:m2:prepare
pnpm test:m2
pnpm test:e2e:m2
```

Они используют выделенную базу `probyu_m2_test` и очищают её синтетические таблицы перед сценариями. Не направляйте тесты на базу с пользовательскими данными. Браузерные тесты сами запускают и останавливают API/web на портах 3104/4174, не затрагивая локальный семейный стенд на 3102/5174. При отсутствии Chromium установите его командой `pnpm --filter @probyu/web exec playwright install chromium`.

При приёмке текущей реализации прошли 23 unit-теста, 21 семейная API/DB-проверка, 14 семейных browser E2E и полный `pnpm verify`. Проверены изоляция семей, отзыв и истечение сессий, согласия, повтор команд, переключение режимов, несколько вкладок и потеря сети. Браузерная проверка выполнена в desktop/mobile Chromium; реальные устройства, production-инфраструктура и настоящий вход этим не проверены.

## Область публичного репозитория

Здесь находится публичная техническая версия проекта: исполняемый код, контракты, миграции, тесты и инструкция запуска. Полная история разработки и внутренняя инженерная документация хранятся в защищённом репозитории и предоставляются организаторам программы для технического аудита по запросу.

Все опубликованные fixtures синтетические. Секреты провайдеров, реальные детские данные и пользовательские credentials в репозиторий не включаются.
